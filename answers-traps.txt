RISC-V assembly

以下地址依据本地当前生成的 user/call.asm；重新编译后地址可能变化。

1. 哪些寄存器用于传递函数参数？main 调用 printf 时，13 在哪里？

RISC-V 调用约定通常使用 a0～a7 传递前八个整数或指针参数。
对于 printf("%d %d\n", f(8) + 1, 13)，a0 保存格式字符串地址，
a1 保存 f(8) + 1 的结果 12，a2 保存 13。
汇编中的 li a2,13 和 li a1,12 与此对应。

2. main 中哪里调用了 f 和 g？

main 中没有实际调用 f 或 g 的指令。编译器消除了这次函数调用，
将 f(8) + 1 = g(8) + 1 = 8 + 3 + 1 提前计算为 12，
因此 main 直接执行 li a1,12。
独立的 f 函数也没有调用 g，而是直接执行 addiw a0,a0,3，
体现了函数内联。main 的最终结果还体现了常量折叠；仅凭最终汇编
无法确定编译器内部各优化步骤的具体顺序。

3. printf 函数位于哪个地址？

当前 printf 的地址为 0x756。main 中的调用指令是：
  0x38: jal 0x756 <printf>

4. main 调用 printf 后，ra 的值是多少？

当前编译结果使用 jal，而不是题目描述的 jalr。
该指令位于 0x38，长度为 4 字节，因此执行后 ra = 0x3c，
即 printf 返回后继续执行的下一条指令地址。

5. 大小端序与 printf 输出。

对于：
  unsigned int i = 0x00646c72;
  printf("H%x Wo%s", 57616, (char *)&i);

输出为（不带换行）：
  He110 World

57616 的十六进制表示为 e110，所以 H%x 输出 He110。
小端序下，i 从低地址到高地址的字节为 72 6c 64 00，
分别对应 'r'、'l'、'd' 和字符串结束符。因此 %s 输出 rld，
与前面的 Wo 拼成 World。

若改用大端序，应将 i 设为 0x726c6400，使内存中的字节顺序
仍为 72 6c 64 00。57616 不需要修改，因为 %x 根据整数数值
进行格式化，不是按内存中的字节顺序输出。

6. printf("x=%d y=%d", 3) 中，y= 后面会打印什么？

没有确定结果；格式字符串需要两个整数，但调用者只提供了一个，
这属于未定义行为。
按当前 RISC-V 参数传递方式，a0 保存格式字符串地址，a1 保存 3，
但没有为第二个整数参数提供有效值。printf 仍会尝试读取它，
在此实现中可能读到 a2 中残留的值，但不能依赖任何具体输出。
